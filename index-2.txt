## 7) Writable Log Files Accessible to Authenticated Users

### Proper Title

**Writable Log Files Accessible to Authenticated Users**

### Active CWE

**CWE-732: Incorrect Permission Assignment for Critical Resource**

### STRIDE Mapping

**2 - Tampering with Data**
**3 - Repudiation**
**6 - Elevation of Privilege**

### CVSS v3.1

**CVSS:3.1/AV:L/AC:L/PR:L/UI:N/S:U/C:L/I:H/A:L = 6.6 (Medium)**

### Why this score

* **AV:L** – attacker requires local authenticated access
* **AC:L** – exploitation is straightforward
* **PR:L** – low-privileged authenticated user sufficient
* **UI:N** – no user interaction required
* **S:U** – impact limited to same system scope
* **C:L** – log data may expose operational details
* **I:H** – attackers can alter or delete audit evidence
* **A:L** – corruption of logs may impact monitoring and troubleshooting

### Affected Asset

* **nec47b36020log1**
* Additional systems where writable logs under non-protected directories were identified

### Description

During authenticated testing, multiple log files stored outside protected Windows system directories were identified with write permissions assigned to low-privileged authenticated users. Access control review showed that authenticated users possessed Modify (`M`) permissions over several log files and directories.

Testing confirmed that log files located outside standard protected paths such as:

* `C:\Windows`
* `C:\Program Files`
* `C:\ProgramData`

could be modified by a normal authenticated user account.

Example permission observed:

```text id="7m4d1c"
NT AUTHORITY\Authenticated Users:(I)(M)
```

### Impact

Improper permissions on log files allow authenticated users to alter, tamper with, or delete audit records, reducing the integrity and reliability of security monitoring mechanisms. An attacker with local access may manipulate logs to conceal malicious activity, remove forensic evidence, or inject misleading records, impacting incident investigation and non-repudiation controls. Writable logs may additionally facilitate privilege escalation or abuse if consumed by privileged processes or monitoring services.

### Steps to Reproduce

1. Enumerate log files:

   ```cmd
   dir C:\*.log /s /b
   ```

2. Identify accessible log files outside protected system directories.

3. Review permissions:

   ```cmd
   icacls "<log_file_path>"
   ```

4. Observe Modify permissions assigned to authenticated users:

   ```text id="bcv73x"
   NT AUTHORITY\Authenticated Users:(I)(M)
   ```

5. Open the identified log file and confirm write access by modifying its contents.

### Resolution

* Restrict write permissions on log files to administrative and required service accounts only.
* Remove Modify permissions assigned to low-privileged or authenticated users.
* Store security and application logs in protected directories with hardened ACLs.
* Enable centralized logging and integrity monitoring for audit records.
* Periodically audit filesystem permissions for sensitive operational files.
