## 2) Information Disclosure via RDP

### Proper Title

**Information Disclosure via Remote Desktop Protocol (RDP) Service Enumeration**

### Active CWE

**CWE-497: Exposure of System Data to an Unauthorized Control Sphere**

### STRIDE Mapping

**4 - Information Disclosure**

### CVSS v3.1

**CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N = 5.3 (Medium)**

### Why this score

* **AV:N** – accessible remotely over the network
* **AC:L** – simple enumeration only
* **PR:N** – no authentication required
* **UI:N** – no user interaction required
* **S:U** – impact limited to same system scope
* **C:L** – internal domain, hostname, OS version, and infrastructure details disclosed
* **I:N / A:N** – no integrity or availability impact observed

### Description

Multiple servers exposed Remote Desktop Protocol (RDP) services externally on port **3389**. During enumeration, the RDP service disclosed internal infrastructure information including:

* Internal Active Directory domain names
* NetBIOS names
* Internal DNS hostnames
* Computer names
* Windows build/version details
* TLS certificate information

This information was retrievable without successful authentication through standard RDP enumeration techniques.

### Impact

The exposed RDP metadata allows attackers to gather valuable reconnaissance information about the internal environment and domain structure. Disclosure of internal hostnames, Active Directory domain details, naming conventions, and operating system versions can assist attackers in infrastructure mapping, phishing preparation, password spraying campaigns, and targeting of known vulnerabilities associated with identified Windows versions or services. The information may also help attackers identify high-value systems and trust relationships within the environment, thereby reducing the effort required for further attacks.

### Steps to Reproduce

1. Perform an Nmap scan against the target host:

   ```bash
   nmap -Pn -sC -sV -p3389 <ip>
   ```

2. Observe the `rdp-ntlm-info` output returned by the service.

3. Verify disclosure of:

   * `Target_Name`
   * `NetBIOS_Domain_Name`
   * `DNS_Domain_Name`
   * `DNS_Computer_Name`
   * `Product_Version`
   * TLS certificate subject details

4. Confirm that the information is accessible without valid authentication.

### Resolution

* Restrict RDP exposure using firewall rules or VPN-only access.
* Limit RDP access to trusted administrative networks.
* Implement Network Level Authentication (NLA) and hardened access controls.
* Avoid unnecessary disclosure of internal infrastructure details through externally reachable services where possible.
* Monitor and restrict unauthorized RDP enumeration attempts.
