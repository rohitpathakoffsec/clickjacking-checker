## 5) Weak SSH Key Exchange Algorithms Supported

### Proper Title

**Weak SSH Key Exchange and Message Authentication Algorithms Supported**

### Active CWE

**CWE-326: Inadequate Encryption Strength**

### STRIDE Mapping

**1 - Spoofing Identity**
**4 - Information Disclosure**

### CVSS v3.1

**CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:L/A:N = 6.5 (Medium)**

### Why this score

* **AV:N** – exploitable remotely over the network
* **AC:L** – attacker only requires network connectivity
* **PR:N** – no authentication required
* **UI:N** – no user interaction required
* **S:U** – impact remains within same security scope
* **C:L** – weak cryptography may expose SSH session confidentiality
* **I:L** – cryptographic downgrade weaknesses may affect integrity protections
* **A:N** – no direct denial-of-service impact demonstrated

### Affected Asset

* **nec47b36020cn01**
* **nstm95035nap**
* Additional SSH-enabled systems where the same algorithms were identified

### Description

SSH services exposed by the assessed systems supported multiple legacy and cryptographically weak key exchange and message authentication algorithms. Enumeration identified deprecated algorithms including:

* `diffie-hellman-group1-sha1`
* `diffie-hellman-group14-sha1`
* `hmac-md5`
* `hmac-sha1`
* `hmac-md5-96`
* `hmac-sha1-96`

These algorithms are considered weak due to the use of deprecated cryptographic primitives such as SHA1 and MD5, which are no longer recommended for secure cryptographic operations.

### Impact

Support for weak SSH cryptographic algorithms increases the risk of cryptographic downgrade attacks and reduces the overall security posture of remote administrative services. Attackers capable of intercepting or manipulating SSH negotiation traffic may attempt to force weaker algorithms during session establishment, potentially weakening confidentiality and integrity protections. Additionally, use of deprecated algorithms may violate modern security hardening standards and enterprise cryptographic compliance requirements.

### Steps to Reproduce

1. Run SSH algorithm enumeration against the target system:

   ```bash
   nmap -Pn --script ssh2-enum-algos -p22 <ip>
   ```

2. Review the returned SSH algorithm list.

3. Observe deprecated algorithms such as:

   ```text id="v7h3cs"
   diffie-hellman-group1-sha1
   hmac-md5
   hmac-sha1
   ```

4. Confirm that weak algorithms are supported by the SSH service.

### Resolution

* Disable deprecated SSH key exchange algorithms.
* Remove support for SHA1- and MD5-based MAC algorithms.
* Enforce modern cryptographic standards such as:

  * `curve25519-sha256`
  * `ecdh-sha2-*`
  * `chacha20-poly1305`
  * SHA2-based MAC algorithms
* Periodically review SSH hardening baselines against current security recommendations.
* Restrict SSH access to trusted administrative hosts.
