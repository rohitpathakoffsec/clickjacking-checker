## 3) Microsoft IIS Server Version Disclosure

### Proper Title

**Microsoft IIS Server Version Disclosure**

### Active CWE

**CWE-497: Exposure of System Data to an Unauthorized Control Sphere**

### STRIDE Mapping

**4 - Information Disclosure**

### CVSS v3.1

**CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N = 5.3 (Medium)**

### Why this score

* **AV:N** – remotely accessible over the network
* **AC:L** – simple request reveals the information
* **PR:N** – no authentication required
* **UI:N** – no user interaction needed
* **S:U** – impact limited to same system
* **C:L** – server technology and exact version details disclosed
* **I:N / A:N** – no direct integrity or availability impact observed

### Affected Asset

* **nec47b36020web2**
* **nec47b36020web3**

### Description

The web servers exposed the exact Microsoft IIS version through HTTP response headers. During testing, the `Server` header disclosed the backend web server as:

```text id="5bm0qs"
Microsoft-IIS/10.0
```

The information was accessible without authentication and could be obtained through standard HTTP requests.

### Impact

Disclosure of the exact IIS server version assists attackers in fingerprinting the target environment and mapping known vulnerabilities associated with the identified software version. Attackers can leverage this information to perform targeted exploitation attempts, vulnerability scanning, or identify applicable public exploits against the disclosed server technology. Although version disclosure alone does not directly compromise the server, it significantly improves the accuracy and efficiency of further attacks against the infrastructure.

### Steps to Reproduce

1. Send an HTTP/HTTPS request to the affected web server:

   ```bash
   curl -I http://<ip>
   ```

   or

   ```bash
   curl -k -I https://<ip>
   ```

2. Observe the HTTP response headers.

3. Verify that the `Server` header discloses:

   ```text id="0omvq4"
   Server: Microsoft-IIS/10.0
   ```

4. Confirm that the information is accessible without authentication.

### Resolution

* Remove or suppress unnecessary HTTP response headers disclosing backend technology details.
* Configure IIS to hide or customize the `Server` header.
* Implement reverse proxy or WAF rules to minimize technology fingerprinting exposure.
* Regularly patch and harden IIS services against publicly known vulnerabilities.

### Evidence

Use screenshots showing:

* Browser response headers
* Burp Suite response
* Curl output
* Nmap service enumeration output

Important evidence to capture:

```text id="jlwmre"
_http-server-header: Microsoft-IIS/10.0
```

or:

```text id="zjdhm0"
Server: Microsoft-IIS/10.0
```
